## Design decision

The checkout invariant is that only one borrower can have an active loan for a given item. Checkout takes a MySQL row lock on the equipment before it checks for an active loan and inserts a record. Delete uses the same equipment lock and rejects items with any loan history, so delete and checkout cannot both succeed for the same item. The public contract and browser form still use the same item and loan IDs. The concurrent check exercises this decision, and the full suite checks that the rest of the API still works.
